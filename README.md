# BridgeBox AI Workforce Intelligence

A multi-tenant web platform that observes **which applications employees use and for how long** (metadata only — never
keystrokes, titles, screenshots or content), mines that activity into repeatable workflows, prices each one with a
transparent financial model, recommends automation (AI agent, RPA, conventional automation, process change, role
consolidation), deploys and supervises agents with approval gates, and measures what was actually saved. A consulting
portal manages many client organizations under one roof.

Stack: Next.js 15 (App Router, server components + server actions), TypeScript strict, Tailwind v4, Drizzle ORM,
Postgres 16 with row-level security, Auth.js v5 (bcrypt + TOTP MFA + optional OIDC SSO), Vitest, Playwright, a
standalone Node collector (`collector/`), optional n8n / Anthropic / Stripe integrations.

Status: **functional pre-production build, not yet used by a paying client.** Read
[`docs/PRODUCTION_READINESS.md`](docs/PRODUCTION_READINESS.md) before promising anything to anyone.

## The three headline numbers

Every executive view reduces to three figures, each with its own evidence basis (`observed` / `estimated` / `assumed`)
and a calculation tree the reader can expand (`<CalcTreeView>`):

| # | Headline | Basis | Source |
|---|---|---|---|
| 1 | **Spent on automatable work today** — annual loaded labor cost of every workflow that has an opportunity (Σ hrs/wk × weeks/yr × hours-weighted loaded hourly), before any automation | observed hours × estimated loaded cost | `src/app/app/page.tsx` (`kpi-wasted`) over `computeOrgFinancials` |
| 2 | **Realistically achievable per year** — realizable annual savings after adoption and realization rates | estimated | `opportunityEconomics` → `realizableAnnualSavings` |
| 3 | **Verified so far** — savings measured from the agent run ledger and before/after observation after deployment | observed | `savings_measurements` (never mixed with projected) |

Projected is always purple, verified always teal. Time saved is never presented as payroll cut; see
[`docs/FINANCIAL_METHOD.md`](docs/FINANCIAL_METHOD.md) §9.

## Quick start

Prerequisites: Node 22 (Node 20+ works), npm 10, Postgres 16 reachable at the URL in `.env`.

```bash
# 1. Postgres: create the role and database (adjust to your local setup)
psql -U postgres -c "CREATE ROLE bridgebox LOGIN PASSWORD 'bridgebox' CREATEDB;"
psql -U postgres -c "CREATE DATABASE bridgebox OWNER bridgebox;"

# 2. Environment
cp .env.example .env
# set AUTH_SECRET (openssl rand -base64 32), VAULT_KEY (openssl rand -base64 32), CRON_SECRET (openssl rand -hex 32)

# 3. Install, migrate + apply RLS + seed synthetic demo data, run
npm i
npm run db:reset
npm run dev          # http://localhost:3000
```

Windows (PowerShell) equivalents and the Docker path are in [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md).

### Demo accounts (`scripts/seed.ts`)

Password for all: `Demo!Pass123` (override with `SEED_PASSWORD` before seeding) — **local development only**. Under a
production runtime (`next start`, Vercel production) these accounts cannot sign in unless `ALLOW_DEMO_LOGINS=1`, the
build never seeds unless `BOOTSTRAP_SEED_DEMO=1`, and production seeding refuses this password (SEC-001,
`docs/SECURITY_VERIFICATION.md`). Running the e2e suite against `npm run start` therefore needs
`ALLOW_DEMO_LOGINS=1 JOBS_KICK_ON_ENQUEUE=0` in the server's environment. **All demo data is synthetic**: the
organizations, people, pay figures and activity are generated by `src/engine/synthetic.ts` (seed 42) and every demo
org is flagged `isDemo`, which watermarks its PDFs "SYNTHETIC DEMO DATA".

## Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Next.js dev server on :3000 |
| `npm run build` / `npm run start` | production build / serve on :3000 |

| `npm run test:e2e` | Playwright acceptance suite (builds + starts the app if :3000 is free) |

## Tests

- **Unit (Vitest):** 129 `it()` cases across 12 files in `tests/unit/` (counted by grep, not by a runner) — mining,
  scoring, costing, finance (+ PDF), analysis end-to-end on the synthetic org, collector ingest API (25), agent runtime
  (13), n8n adapter (mocked fetch), billing (mocked Stripe), onboarding, assistant, process-mining mappers. Most
  suites need a real Postgres; point `DATABASE_URL` at a scratch database, never the seeded one
  (`DATABASE_URL=postgresql://bridgebox:bridgebox@localhost:5432/bridgebox_test npx vitest run`).
- **E2E (Playwright):** 35 tests (4 login setups + 29 desktop + 2 mobile) in `tests/e2e/`, serial, against the
  production build and the seeded database. `npm run db:reset && npm run test:e2e`. The four application bugs the
  suite originally found (`tests/e2e/FINDINGS.md`) are fixed in code; see `docs/PRODUCTION_READINESS.md`.
- **CI:** `.github/workflows/ci.yml` — Postgres 16 service, `npm ci`, migrate + seed, `tsc`, Vitest, `next build`,
  then Playwright with Chromium.
